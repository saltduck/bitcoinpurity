# TASK-20261116-0125-01: Default RPC binding without IPv6

Status: implemented; verified on Linux without the IPv6 address family. Not
verified on a host with IPv6 loopback or on Windows.

Since #44 (`f5a8a87f5d`) numeric RPC bind addresses resolve with
AI_NUMERICHOST. On a kernel without IPv6, `getaddrinfo("::1")` then succeeds
and `socket(AF_INET6)` fails with EAFNOSUPPORT, which `HTTPBindAddresses`
counted as a failure, so `bitcoind` did not start with default RPC settings.

`my_bind_socket_with_handle` now sets `ignorable_error` when `socket()` fails
with an unsupported address family, read before `evutil_freeaddrinfo` can
change the error. `HTTPBindAddresses` is unchanged: it ignores the error only
for the default endpoints, so explicit `-rpcbind` still fails. The comparison
uses `WSAEAFNOSUPPORT`, which `compat.h` maps to `EAFNOSUPPORT` off Windows;
on Windows `EVUTIL_SOCKET_ERROR()` is `WSAGetLastError()` and `EAFNOSUPPORT`
from `errno.h` would never match.

Test changes: `rpc_bind.py --ipv4` on a host without IPv6 loopback also checks
that default settings bind only `127.0.0.1` and log the ignored `::1` endpoint,
and that `-rpcallowip=[::1] -rpcbind=[::1]` fails startup. `get_bind_addrs`
skips `/proc/net/tcp6` when it does not exist; without that every bind test
failed on such hosts before reaching the node check.

Requirement entry, product specification, SV2 architecture/API documents,
migration report and task index are synchronized.
